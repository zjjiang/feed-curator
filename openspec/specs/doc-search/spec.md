## Purpose

为 AI agent（经 MCP 调用）提供对本地语料的检索与深读能力：按关键词查找相关文档并取回内容片段，按文档标识读取全文。检索是纯读路径，建立在文档与实体内容之上，不依赖判定层是否已有结果。

## Requirements

### Requirement: 关键词检索

系统 SHALL 提供关键词检索：agent 提交查询词，系统返回按相关性排序的文档列表，每条结果 MUST 包含文档标识、标题、URL、取自文档内容的相关片段；文档已有判定结果时，结果 MUST 附带星级与领域信息，判定缺失时 MUST NOT 因此排除该文档。

检索 MUST 支持以下过滤条件，且过滤条件之间为 AND 关系：实体类型（article / paper / repo）、领域（按 AI 判定归属）、时间窗口（按统一排序时间）。所有过滤条件 MUST 为可选。

系统 MUST 对中文内容分词建立索引，并以同一种分词方式处理查询词；查询词为空或全部为停用词时 MUST 返回参数错误而非空结果集。无命中时 MUST 返回成功响应并说明无结果，附可调整的建议（放宽过滤、更换关键词）。

#### Scenario: 中文关键词命中正文

- **WHEN** agent 以「多智能体协作」检索
- **THEN** 系统返回正文中包含该主题的文档，按相关性排序
- **AND** 每条结果附有取自正文的片段，片段 MUST 能体现命中位置

#### Scenario: 标题与内容均可命中

- **WHEN** 查询词仅出现在某文档的标题中，另一文档仅出现在正文中
- **THEN** 两篇文档 MUST 均可被检索到

#### Scenario: 过滤条件组合

- **WHEN** agent 以查询词加「仅论文、最近 30 天」的组合检索
- **THEN** 结果 MUST 只含排序时间在窗口内的论文实体
- **AND** 不满足过滤但内容命中的文档 MUST NOT 出现在结果中

#### Scenario: 判定缺失不排除

- **WHEN** 某文档内容命中但尚无判定结果
- **THEN** 该文档 MUST 正常出现在结果中，星级与领域字段为空

#### Scenario: 无结果时给出可操作反馈

- **WHEN** 查询词在语料中无任何命中
- **THEN** 系统返回成功响应，结果为空
- **AND** 响应 MUST 说明无命中，MUST 附带放宽或调整查询的建议

#### Scenario: 空查询拒绝

- **WHEN** agent 提交空字符串或纯空白查询词
- **THEN** 系统 MUST 返回参数错误并说明原因

### Requirement: 全文读取

系统 SHALL 提供按文档标识读取全文的工具：返回文档的标题、URL、实体类型与全文内容（article 正文 / paper 摘要 / repo README），文档已有判定时 MUST 附带最新一次成功判定的摘要与要点。

文档标识不存在时 MUST 返回明确的失败信息。全文内容超过返回上限时，系统 SHALL 返回开头部分并说明已截断及总长度，MUST NOT 静默丢弃。

#### Scenario: 读取文章全文

- **WHEN** agent 以某文章的文档标识读取
- **THEN** 系统返回标题、URL 与正文全文
- **AND** 若该文档已有成功判定，附最新摘要与要点

#### Scenario: 三类实体内容齐备

- **WHEN** 分别读取文章、论文、工程项目三类文档
- **THEN** 返回内容分别对应正文、摘要、README
- **AND** MUST NOT 因实体类型不同而失败

#### Scenario: 文档不存在

- **WHEN** agent 以不存在的文档标识读取
- **THEN** 系统 MUST 返回失败并说明文档不存在

#### Scenario: 超长内容截断说明

- **WHEN** 某文档全文超过单次返回上限
- **THEN** 系统返回开头部分
- **AND** 响应 MUST 标明已截断与全文总长度

### Requirement: 索引随写入保持可检索

检索索引 SHALL 为可全量重建的派生数据：索引 MUST NOT 承载唯一数据，任一时刻删除索引文件后 MUST 能仅凭数据库内容完整重建。文档写入（管道采集、手工存入、再次采集补空）完成后，系统 SHALL 使索引与新数据一致，新入库文档在此后的检索中 MUST 可被命中。

索引不可用（缺失或损坏）时，检索工具 MUST 返回明确的失败信息而非崩溃，且失败信息 MUST 能提示触发重建。索引重建失败 MUST NOT 影响文档写入主流程。

#### Scenario: 管道新入库文档可检索

- **WHEN** 某管道采集新入库一篇文档，完成后 agent 以该文档特有的关键词检索
- **THEN** 该文档 MUST 出现在结果中

#### Scenario: 手工存入文档可检索

- **WHEN** 用户经手工存入提交一个 URL，入库完成后 agent 检索其内容特征词
- **THEN** 该文档 MUST 可被命中

#### Scenario: 索引可全量重建

- **WHEN** 索引文件被删除后触发重建
- **THEN** 重建仅使用数据库现有数据即可完成
- **AND** 重建后检索结果恢复一致

#### Scenario: 索引不可用时明确报错

- **WHEN** 索引缺失或损坏时 agent 发起检索
- **THEN** 系统 MUST 返回失败并提示可触发重建
- **AND** MUST NOT 抛出未处理异常

#### Scenario: 重建失败不阻塞写入

- **WHEN** 索引重建过程中发生错误
- **THEN** 该错误 MUST 被记录且不影响已完成的文档写入
- **AND** 文档写入 MUST NOT 因索引失败而回滚

### Requirement: 索引状态可查

系统 SHALL 在运维界面展示检索索引的覆盖状态:文档总数、已入索引数,以及未入索引文档的清单(标题与实体类型)。状态数据 MUST 实时来自当前索引与数据库的对比,而非缓存快照。

系统 SHALL 提供手动重建索引的入口。重建 MUST 按派生数据语义执行(仅凭数据库重建),MUST NOT 修改任何文档数据;重建结果(成功或失败)MUST 反馈到界面。

#### Scenario: 覆盖状态展示

- **WHEN** 用户打开运维界面
- **THEN** 页面显示文档总数与已入索引数
- **AND** 显示索引的上次构建时间

#### Scenario: 未入索引文档可见

- **WHEN** 存在未入索引的文档(如内容为空、分词后无有效 token)
- **THEN** 运维界面 MUST 列出这些文档的标题与实体类型
- **AND** 已全部覆盖时 MUST 显示全覆盖状态而非空清单

#### Scenario: 手动重建不影响数据

- **WHEN** 用户在运维界面触发索引重建
- **THEN** 系统 SHALL 仅凭数据库内容全量重建索引
- **AND** 文档、判定、管道数据 MUST NOT 发生任何变化
- **AND** 重建结果 MUST 反馈到界面
